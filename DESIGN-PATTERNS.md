# Burnfolder — Design & Usability Patterns

A living reference for the visual, interaction, and code conventions that keep Burnfolder pages from turning into one-off clunky first passes. If you are building a new page, panel, grid, or menu, start here.

**Scope:** this doc covers the public site and the Studio tools. It is not an inspiration board of other artists’ sites; it is an internal standard library of patterns that already work in this codebase.

---

## 1. Page shells

### Public pages

Every public page follows the same container rule:

```html
<div class="page-wrap">
  <!-- page content -->
</div>
```

- Default `.page-wrap` is `max-width: 480px`, `margin: 0 0 0 60px`, with left gutter room for the constellation menu.
- Pages that need more breathing room (album, video, etc.) add a modifier class: `album-page-wrap` is `max-width: 920px`.
- The shared site menu injects itself before the bottom player and adds `padding-top: 56px` to `.page-wrap` automatically.
- When a section name is shown in the menu toggle, the first `.page-id` inside `.page-wrap` is hidden automatically via `:has(.site-menu__current)`.

**Pattern:** one wrapper, one modifier, no custom per-page outer containers.

### Studio pages

Studio pages use `.studio-page` on `<body>` and typically mount their own layout shell (e.g. `.studio-clips-layout`). They do not reuse `.page-wrap`.

## 2. Tokens

### Color

```css
:root {
  --c-black: #000;
  --c-white: #fff;
  --c-gray: #c8c8c8;
  --c-media-link: #000;
}
```

Use the tokens. Do not invent new grays for one page.

### Typography

```css
:root {
  --font-site: "Hibur Mono", ui-monospace, monospace;
  --type-size: 0.95em;
}
```

- Public page text is lowercase sitewide via `text-transform: lowercase` on `html`.
- Studio pages are also lowercase and use the same font stack.
- If you find yourself setting `font-family: var(--font-site)` on more than one element in a component, you are probably missing a parent-level rule.

### Spacing

- Public pages: `24px–28px` vertical rhythm, `12px–16px` small gaps.
- Studio: `16px–20px` panels, `10px–14px` section gaps.
- Avoid magic numbers. Use `rem` for user-scaling.

## 3. Site navigation

The site menu is generated by <ref_file file="/Volumes/BURNFOLDER/PROJECTS/Burnfolder/Burnfolder.com/BURNFOLDER.COM (MAIN)/shared/site-menu.js" />.

### Rules

- Every public HTML page must have `<div id="siteMenu"></div>` at the top of `<body>`.
- The menu is mounted automatically; do not add a second `<header>`.
- Section detection is by pathname (`audio.html` → `audio`, etc.). If you add a new section, update `NAV_ITEMS` and `detectCurrentSection`.
- Active state is shown in the toggle via `.site-menu__current`; the panel item gets `.is-current` and `aria-current="page"`.
- Unassigned pages use `href`-less `<span>` items with `aria-disabled="true"`.

### Preview mode

The Studio menus page can inject preview CSS via `?__menu_preview=1&__menu_css=...&__menu_section=...`. The menu script writes a `<style id="siteMenuPreviewCss">` block. This is the only place custom menu CSS should enter the public page.

## 4. Album hub pattern

The public album page (<ref_file file="/Volumes/BURNFOLDER/PROJECTS/Burnfolder/Burnfolder.com/BURNFOLDER.COM (MAIN)/album.html" />) now renders through <ref_file file="/Volumes/BURNFOLDER/PROJECTS/Burnfolder/Burnfolder.com/BURNFOLDER.COM (MAIN)/shared/album-hub-render.js" />.

### Structure

```
.album-hub
├── .album-hub__site          (burnfolder — album title)
├── .album-hub__chrome
│   ├── .album-hub__cover      (button, square)
│   └── .album-hub__meta
│       ├── .album-hub__title
│       ├── .album-hub__credits
│       └── .album-hub__actions
├── .album-hub__grid           (track tiles)
└── .album-hub__panel-mount     (inline details panel)
```

### Why this works

- The cover, title, credits, and primary play action are grouped in one chrome block.
- Tracks are square tiles in an `auto-fill` grid; clicking a tile opens an inline panel instead of navigating away.
- The inline panel uses `hidden` and is replaced on each tile click, so there is no modal complexity.
- The renderer delegates media-card rendering to the existing song renderer if available, avoiding duplicate markup.

### CSS notes

- BEM naming: block `album-hub`, elements `album-hub__element`, state `is-empty`.
- Square tiles use `aspect-ratio: 1`.
- Cover defaults to `180px × 180px`; on mobile it shrinks to `140px × 140px`.
- Panel sits below the grid with `border-top` and a close button.

### When building a similar hub

1. One root container, one modifier class on `.page-wrap`.
2. Header/site label, chrome/meta, grid, inline panel.
3. Use `button` for interactive tiles, not `<a>` unless the tile is purely navigation.
4. Always provide an empty/fallback message when a panel has no content.

## 5. Studio focus pane pattern

The Clips page opens song/album editors in a focus pane instead of navigating away.

### Structure

```html
<div id="clipsFocusPane" class="clips-focus-pane" hidden></div>
```

```css
body.clips-focus-open {
  overflow: hidden;
}
body.clips-focus-open .studio-clips-layout {
  filter: brightness(0.85);
  pointer-events: none;
}
.clips-focus-pane {
  position: fixed;
  top: 0;
  right: 0;
  bottom: 0;
  width: 55vw;
  min-width: 420px;
  max-width: 720px;
  z-index: 200;
  background: #fff;
  border-left: 1px solid rgba(0, 0, 0, 0.12);
  overflow: auto;
}
```

### Behavior

- Mount: show the pane, add `clips-focus-open` to body, dim and disable the background layout.
- Destroy: tear down the mounted module instance, hide the pane, remove the class, clean URL params.
- Sync URL: `?song=` or `?album=` so refresh/bookmark restores the focus pane.
- Close via in-pane close button or `Escape`.

### Inside the pane

```
.studio-focus
├── .studio-focus-header       (sticky, title + close)
├── .studio-focus-body
│   ├── .studio-focus-section
│   │   ├── .studio-focus-section-title
│   │   └── .studio-focus-section-head (title + actions)
│   └── .studio-focus-preview-wrap
```

### Pattern checklist

- [ ] Pane is a single reusable DOM node, hidden by default.
- [ ] Only one focus module is active at a time; `destroyFocus()` clears any prior instance.
- [ ] URL state is updated with `history.replaceState`, not `pushState`.
- [ ] Body scroll is locked while open.
- [ ] Mobile: pane becomes full-width (`100vw`).

## 6. Cards, tiles, and grids

### Public grids

Use `repeat(auto-fill, minmax(140px, 1fr))` for dense media grids (album tracks, media cards).

```css
.album-hub__grid,
.album-hub__media-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(140px, 1fr));
  gap: 12px;
}
```

### Studio grids

Studio archive/version lists use slightly smaller min widths (`130px`) to fit more items.

### Tile pattern

- The tile itself is a `button` if it triggers an action.
- Title sits absolute at the edges so the whole tile remains clickable.
- Provide `:hover`, `:focus-visible`, and `:active` states.
- Empty state: show text centered inside a dashed placeholder.

---

## 7. Inline panels and details

The album hub uses an inline details panel below the grid. Prefer this over modals for:

- Track details, lyrics, notes
- Media previews
- Item metadata

Rules:

- Replace panel content, do not stack panels.
- Close button is `type="button"` with `aria-label`.
- Use `hidden` attribute, not `display: none` inline styles, unless dynamic toggling requires it.
- If no content exists, render an empty message rather than a blank panel.

## 8. Buttons and actions

### Button reset base

The project uses a minimal reset for icon/action buttons:

```css
.icon-btn {
  appearance: none;
  background: transparent;
  border: none;
  border-radius: 0;
  cursor: pointer;
  padding: 0;
}
```

### Action groups

Use flex with `gap`:

```css
.album-hub__actions {
  display: flex;
  gap: 10px;
}
```

### Touch targets

Minimum `44px × 44px` for any tap target (play buttons, close buttons, tiles).

### Studio action menus

Clips blocks have a small action menu. Keep menus small, deterministic, and close on outside click or `Escape`.

## 9. Empty, loading, and error states

### Album hub examples

- No album ID or unknown album: `<p class="page-annotation">Album not found.</p>`
- Panel with no notes/lyrics/media: `<p class="album-hub__panel-empty">no more info yet.</p>`

### Rules

1. **Empty** ≠ **Loading** ≠ **Error**. Render them differently.
2. Empty states should tell the user what is missing and ideally offer a next action.
3. Error states should not expose internals. “Album not found” is enough.
4. If data is fetched async, show a loading state or placeholder; do not render a misleading empty state.

## 10. SPA routing and state

### Public site

- `spa-router.js` handles soft navigation.
- Custom event `burnfolder-spa-navigated` is fired after navigation; the menu re-mounts on it.
- The bottom player and now-playing state persist across soft navigations.

### Studio Clips

- `activateBlock()` routes block clicks by `kind`.
- Focus panes sync state to URL params (`?song=`, `?album=`) so a refresh restores context.
- `closeFocus()` removes params via `history.replaceState`.

### Rule

If a state change should survive a refresh, put it in the URL. If it should not, keep it in module-local state.

## 11. Animation and motion

### Defaults

- Subtle, short transitions only.
- Use `transform` and `opacity`, never `width`/`height`/`top`/`left` for animation.
- Tile active state: `transform: scale(0.985)` on `:active`.
- Focus pane appearance: no animation by default; the brightness change on the background is enough orientation.

### Respect reduced motion

If you add entrance animations, wrap them in:

```css
@media (prefers-reduced-motion: no-preference) {
  /* animation here */
}
```

## 12. Naming conventions

### CSS

- Public components: BEM-ish block names, double-underscore elements, double-hyphen modifiers.
  - `.album-hub`, `.album-hub__cover`, `.album-hub__cover.is-empty`
- Studio components: kebab-case, often prefixed with `studio-`.
  - `.studio-focus`, `.clips-focus-pane`, `.studio-focus-header`
- State classes usually start with `is-` or `has-`.
  - `.is-current`, `.is-open`, `.is-empty`, `body.clips-focus-open`

### JS

- Global module namespace: `Burnfolder{Feature}`
  - `BurnfolderAlbumHubRender`, `BurnfolderSiteMenu`, `BurnfolderSongFocus`
- Module exposes a small public object with `mount`, `apply`, `destroy`, etc.
- DOM helpers should live in one place; do not recreate `escapeHtml` in every file.

### Files

- Shared public code: `/shared/`
- Studio code: `/studio/js/`, `/studio/css/`, `/studio/`
- Page-specific bootstrapping can live in root HTML inline or in a dedicated `*-boot.js`.

## 13. Anti-patterns

These are the clunky first-pass habits to avoid.

### Adding a new page when a focus pane will do

Before creating `studio/new-thing.html`, ask: could this live inside Clips as a focus pane? Standalone pages require routing, menu handling, and reload behavior. Focus panes reuse the Clips context.

### Per-page global CSS

Do not write rules like `.some-page-only-class { … }` at the top level of `style.css` unless the component is truly reusable. If it only applies to one page, scope it under a page class or keep it in a page-specific stylesheet.

### Inline event handlers

Use `addEventListener` in the module that owns the element. Avoid `onclick="…"` in HTML.

### Duplicate escape/sanitize helpers

`escapeHtml` exists in multiple files because the old pattern grew organically. New code should reuse a shared helper or import one. Do not copy-paste HTML escaping.

### Modal-first design

Inline panels and focus panes are preferred over lightboxes and modals. Modals break mobile scrolling, trap focus incorrectly, and fight the bottom player.

### Ignoring the menu

If a new public page does not declare `<div id="siteMenu"></div>` or if it adds its own `<header>`, the constellation navigation will break or duplicate.
